7.1

Python Classes

A class is a blueprint or template that defines the structure and behavior of objects. It groups related data (attributes) and functions (methods) into a single logical unit.

What is a Class?

A class is a user-defined data type that contains attributes (variables) and methods (functions). Think of it as a template from which you create individual objects. For example, a Student class might define that every student has a name, age, and grade - but each actual student object has specific values for these attributes.

Class Syntax
class ClassName:
    """Docstring describing the class."""
    
    def __init__(self, param1, param2):
        self.attribute1 = param1
        self.attribute2 = param2
    
    def method_name(self):
        # Method logic here
        pass
# Define a Student class
class Student:
    """A class to represent a student."""
    
    def __init__(self, name, age, marks):
        self.name = name
        self.age = age
        self.marks = marks
    
    def display(self):
        print(f"Name: {self.name}, Age: {self.age}, Marks: {self.marks}")

# Create objects from the class
s1 = Student("Rama", 15, 80)
s2 = Student("Krishna", 12, 60)

# Access attributes
print(s1.name)   # Rama
print(s2.marks)  # 60

# Call methods
s1.display()  # Name: Rama, Age: 15, Marks: 80
Advantages of Classes
  • Organization: Group related data and functions together
  • Reusability: Create multiple objects from one class
  • Inheritance: Extend classes to add new features
  • Readability: Clear structure makes code easier to understand
  • Maintainability: Changes in one place affect all objects
7.2

Python Objects

An object is an instance of a class. When you create an object, you're creating a specific entity with its own data values based on the class blueprint.

Object Components

Every object has three components:

  • State: The data/attributes (e.g., name, age)
  • Behavior: The methods/functions it can perform
  • Identity: A unique identifier distinguishing it from other objects

# Define the Person class
class Person:
    def __init__(self, name, age, profession):
        self.name = name
        self.age = age
        self.profession = profession
    
    def work(self):
        print(f"{self.name} is working as a {self.profession}")

        print(f"{self.name} is studying")

# Create objects (instances)
jessa = Person("Jessa", 28, "Software Engineer")

# Each object has its own state
jessa.work()  # Jessa is working as a Software Engineer
jon.work()    # Jon is working as a Lawyer
7.3

The __init__ Constructor

The __init__ method is a special method called the constructor. It's automatically called when you create a new object and is used to initialize the object's attributes.

Understanding self

self is a reference to the current instance of the class. It allows you to access the object's attributes and methods from within the class. The first parameter of every instance method must be self (though you can technically name it anything).

class BankAccount:
    def __init__(self, owner, balance=0):
        """Initialize account with owner and optional balance."""
        self.owner = owner       # Required
        self.balance = balance   # Default value: 0
        print(f"Account created for {owner}")
    
    def deposit(self, amount):
        self.balance += amount
        print(f"Deposited ${amount}. New balance: ${self.balance}")
    
    def withdraw(self, amount):
        if amount <= self.balance:
            self.balance -= amount
            print(f"Withdrew ${amount}. Remaining: ${self.balance}")
        else:
            print("Insufficient funds!")

# Create accounts
acc1 = BankAccount("Alice")           # Account created for Alice
acc2 = BankAccount("Bob", 1000)       # Account created for Bob

# Use methods
acc1.deposit(500)     # Deposited $500. New balance: $500
acc2.withdraw(200)    # Withdrew $200. Remaining: $800
📝’¡ Key Points about __init__
  • Called automatically when creating an object
  • Used to initialize instance attributes
  • Can have default parameter values
  • Does NOT return anything (implicitly returns None)
7.4

Instance vs Class Variables

Python has two types of variables in classes: instance variables (unique to each object) and class variables (shared by all objects).

Instance Variables Class Variables
Defined inside __init__ using self Defined directly in the class body
Unique to each object Shared by all objects
Access: self.variable Access: ClassName.variable
Each object has its own copy One copy for the entire class 
class Student:
    # Class variable - shared by ALL students
    school_name = "Quanskill Academy"
    student_count = 0
    
    def __init__(self, name, grade):
        # Instance variables - unique to each student
        self.name = name
        self.grade = grade
        # Increment class variable
        Student.student_count += 1
    
    def display(self):
        print(f"{self.name} studies at {Student.school_name}")

# Create students
s1 = Student("Alice", "A")
s2 = Student("Bob", "B")

# Instance variables are different
print(s1.name)  # Alice
print(s2.name)  # Bob

# Class variable is shared
print(Student.school_name)  # Quanskill Academy
print(Student.student_count)  # 2

# Changing class variable affects all
Student.school_name = "New Academy"
s1.display()  # Alice studies at New Academy
s2.display()  # Bob studies at New Academy
When to Use Each
  • Instance variables: Data unique to each object (name, age, balance)
  • Class variables: Data shared across all objects (counters, constants, default settings)
7.5

Method Types

Python classes support three types of methods: instance methods, class methods, and static methods.

Instance Method

Access/modify object state

def method(self):
Class Method

Access/modify class state

@classmethod
def method(cls):
Static Method

Utility function, no state access

@staticmethod
def method(): 
class Calculator:
    # Class variable
    version = "1.0"
    
    def __init__(self, name):
        self.name = name
    
    # Instance method - uses self
    def greet(self):
        print(f"Calculator: {self.name}")
    
    # Class method - uses cls (the class)
    @classmethod
    def get_version(cls):
        return f"Version: {cls.version}"
    
    # Static method - no self or cls
    @staticmethod
    def add(x, y):
        return x + y
    
    @staticmethod
    def multiply(x, y):
        return x * y

# Using instance method
calc = Calculator("MyCalc")
calc.greet()  # Calculator: MyCalc

# Using class method
print(Calculator.get_version())  # Version: 1.0

# Using static methods
print(Calculator.add(5, 3))       # 8
print(Calculator.multiply(4, 7))  # 28
When to Use Each Method Type
  • Instance method: When you need to access/modify object attributes
  • Class method: When you need to access/modify class variables or create alternative constructors
  • Static method: Utility functions that logically belong to the class but don't need class/instance data
7.6

Access Specifiers

Python uses naming conventions to indicate the intended visibility of attributes and methods. Unlike some languages, Python doesn't enforce strict access control - it relies on programmer discipline.

Convention Prefix Access Example
Public None Accessible everywhere self.name
Protected _ Internal use (convention only) self._internal
Private __ Name mangling applied self.__secret 
class Student:
    def __init__(self, name, age, rollno):
        self.name = name          # Public
        self._age = age           # Protected (convention)
        self.__rollno = rollno    # Private (name mangling)
    
    def display(self):
        # Can access all attributes inside class
        print(f"{self.name}, {self._age}, {self.__rollno}")
    
    def get_rollno(self):
        # Getter method for private attribute
        return self.__rollno

s = Student("Alice", 20, 12345)

# Public - accessible
print(s.name)  # Alice

# Protected - accessible but discouraged
print(s._age)  # 20

# Private - NOT directly accessible
# print(s.__rollno)  # AttributeError!

# Access via getter method
print(s.get_rollno())  # 12345

# Private is still accessible via name mangling (not recommended)
print(s._Student__rollno)  # 12345
âš  Python's Philosophy

Python follows "We're all consenting adults here." Access specifiers are conventions, not strict enforcement. Use _ to signal "internal use" and __ for name mangling when you want to avoid accidental overrides in subclasses.

7.7

Inheritance

Inheritance allows a class (child/derived) to inherit attributes and methods from another class (parent/base). This promotes code reuse and establishes an "is-a" relationship.

Inheritance Concept

A child class inherits all the attributes and methods from its parent class. The child can also add new attributes/methods or override inherited ones to provide specialized behavior.

# Parent class
class Animal:
    def __init__(self, name):
        self.name = name
    
    def speak(self):
        print(f"{self.name} makes a sound")
    
    def eat(self):
        print(f"{self.name} is eating")

# Child class - inherits from Animal
class Dog(Animal):
    def __init__(self, name, breed):
        # Call parent constructor
        super().__init__(name)
        self.breed = breed
    
    # Override parent method
    def speak(self):
        print(f"{self.name} barks: Woof!")
    
    # New method specific to Dog
    def fetch(self):
        print(f"{self.name} is fetching the ball")

# Another child class
class Cat(Animal):
    def speak(self):
        print(f"{self.name} meows: Meow!")

# Create objects
dog = Dog("Buddy", "Golden Retriever")
cat = Cat("Whiskers")

# Inherited method
dog.eat()    # Buddy is eating
cat.eat()    # Whiskers is eating

# Overridden method
dog.speak()  # Buddy barks: Woof!
cat.speak()  # Whiskers meows: Meow!

# Dog-specific method
dog.fetch()  # Buddy is fetching the ball
The super() Function

super() returns a proxy object that allows you to call methods from the parent class. It's commonly used in __init__ to initialize inherited attributes before adding new ones.

Quick Check

If Dog inherits from Animal, and Animal has an eat() method, what happens when you call dog.eat()?

Error: Dog doesn't have eat()
Animal's eat() method is called
Nothing happens
You must define eat() in Dog
Correct! Dog inherits eat() from Animal, so the parent's method is used unless Dog overrides it.
Remember: inheritance means the child automatically gets all parent methods unless it overrides them.
7.8

Encapsulation

Encapsulation is the bundling of data and methods that operate on that data within a single unit (class), while restricting direct access to some components. This protects internal state from unintended modification.

Why Encapsulation?
  • Data Protection: Prevent invalid data from being set
  • Controlled Access: Use getters/setters to validate changes
  • Flexibility: Change internal implementation without affecting external code
  • Abstraction: Hide complex internal workings
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.__balance = balance  # Private attribute
    
    # Getter - controlled read access
    def get_balance(self):
        return self.__balance
    
    # Setter - controlled write access with validation
    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
            return True
        print("Deposit must be positive!")
        return False
    
    def withdraw(self, amount):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
            return True
        print("Invalid withdrawal amount!")
        return False

# Create account
account = BankAccount("Alice", 1000)

# Can't access balance directly
# print(account.__balance)  # AttributeError!

# Must use getter
print(account.get_balance())  # 1000

# Deposit with validation
account.deposit(500)   # Works
account.deposit(-100)  # Deposit must be positive!

# Withdraw with validation
account.withdraw(200)   # Works
account.withdraw(5000)  # Invalid withdrawal amount!

print(account.get_balance())  # 1300
Data Science Example: Protected Model 
class MLModel:
    def __init__(self):
        self.__weights = None  # Private
        self.__is_trained = False
    
    def train(self, X, y):
        # Training logic here
        self.__weights = "trained_weights"
        self.__is_trained = True
    
    def predict(self, X):
        if not self.__is_trained:
            raise Exception("Model must be trained first!")
        # Use weights for prediction
        return "predictions"
